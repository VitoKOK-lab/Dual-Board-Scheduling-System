# 雙板動態排班系統 Dual-Board Scheduling System

數位化實體「黑板（週矩陣）」與「白板（區域矩陣）」，提供排班主管一鍵極速排班、完全覆寫權與自動公平輪替。

* **使用者**：排班主管單一角色，單向由上而下發布。
* **編制**：師傅 22 位（高二組）進入排班池；徒弟 47 位（高一組）不排班、不計入點位人數，
  由主管手動升級為師傅後才會被排到班。
* **介面**：100% 手機優先的單頁看板（375px 起跳，支援深色模式與列印）。
* **系統邊界**：僅處理計畫班表，不涉及打卡、薪資與勞基法限制。主管具 100% 強制覆寫權。
* **技術**：Node.js 22 + 內建 `node:sqlite` + 原生前端，**零 npm 相依套件**。

---

## 兩種跑法

**伺服器版**（本機或內網，資料存在 SQLite）：見下方快速開始。

**單頁版**（`docs/index.html`，可直接放上靜態主機）：

```bash
node scripts/build-web.mjs   # 產生 docs/index.html
```

`docs/` 是 GitHub Pages 的標準來源目錄。在 repo 的
Settings → Pages 選 **Deploy from a branch → 分支 → /docs** 就會有公開網址，
不用登入、不用伺服器。

建置會把 `src/db/seed.sql` 的名冊與點位**內嵌進頁面**，第一次打開就有
69 人、55 個點位／任務可用，不必手動建。之後所有異動都存在瀏覽器本機，
**務必用設定裡的匯出備份**——清掉瀏覽器資料或換手機就會消失。

建置產出兩份，內容相同只差外框：

| 檔案 | 給誰 | 差別 |
|---|---|---|
| `docs/index.html` | 靜態主機 | 完整 HTML 文件，含 viewport meta |
| `web/artifact.html` | Claude Artifact | 只有內容，平台發布時自己補外框 |

這件事不能混：靜態主機不會補 viewport meta，少了它手機會用 980px
桌面寬度渲染再縮小，整個介面變成一團小字。

領域邏輯（`src/domain`：排班引擎、公平性、Plan X）本來就是純函式、不碰資料庫，
兩種跑法共用同一份。只有資料層不同：

| | 伺服器版 | 單頁版 |
|---|---|---|
| 儲存 | SQLite（`src/db`） | 瀏覽器本機；放在 Artifact 上時改用雲端儲存 |
| 資料存取 | `src/services/repository.js` | `web/store.js` |
| 服務層 | `src/services/scheduleService.js` | `web/services.js` |
| API | `src/server`（REST） | `web/dispatch.js`（同樣的路徑與回傳格式） |
| 看板 | `public/app.js` | 同一份，建置時做 5 處修補 |

建置腳本的修補如果對不上 `public/app.js` 會直接失敗，不會默默產出壞掉的頁面。

## 快速開始

```bash
npm run reset    # 建立資料庫並灌入名冊（69 位人員、55 個點位／任務）
npm start        # http://localhost:3000
npm test         # 88 個測試
```

環境變數：`PORT`（預設 3000）、`HOST`（預設 0.0.0.0）、`DB_PATH`（預設 `data/scheduling.db`）。

## 排班演算法（規格 §4）

引擎是**純函式**：輸入人員、點位字典、公平性統計、升旗日與週起始日，輸出整週指派。相同輸入必得相同班表。

**排班池只有師傅**。徒弟不排班、不計入點位人數，也不會出現在班表上。

白板分**三個時段**，其中兩個是常態、一個是事件：

* **早修**與**午休**：**依週指派**。一個點位整週同一人，週一到週五都一樣，一週洗牌一次。
* **升旗**：**事件**，一個月約三次。主管在白板的升旗頁指定哪幾天升旗，
  排班時所有師傅的名牌才會排到升旗表上；沒指定就整塊空著。
  升旗底下再分「定點」與「巡查」兩種任務，兩者屬同一時段、共用名額上限。

執行順序：

| 步驟 | 內容 | 硬性限制 | 軟性限制（可放寬） |
|---|---|---|---|
| A | 黑板全週職務（交接、值日生） | 不重複擔任其他全週職務 | — |
| B | 黑板每日職務（餐車、早修、午休、校表） | 當日無其他黑板任務 | 非全週職務持有者 |
| C | 白板早修 → 午休（依週指派） | **該時段整週僅站一個點位**、**本週不重複站同一點位** | — |
| D | 白板升旗（僅在指定的升旗日） | 同一個升旗日僅站一個點位 | — |

**公差不在這裡**：它是隊裡的特殊任務，由主管手動指派，重新排班不會動到它。

**每個人都要有任務**：所有可排班的師傅一律進入候選池，沒有預備隊、沒有人被刻意排除。
生成後若仍有人整週掛零（名額少於人數時才會發生），回報 `IDLE_STAFF` 並列出是誰。

### 人力上限（會直接限制點位設定）

每人每個時段只能站一個點位，因此**單一時段的名額總數不能超過可排班的師傅數**。
系統在「統計」頁列出師傅數與各時段名額，超過上限時回報 `CAPACITY_EXCEEDED`。

目前配置（取自主管提供的班表範本，每點 1 人）：
早修 10 點、升旗 19 點（定點 11 + 巡查 8）、午休 12 點，黑板全週 2 項 + 每日 4 項，
公差 8 項。尖峰是升旗 19 個名額，22 位師傅足夠。

白板改依週指派後，一般週的自動排班名額是 2（全週）+ 20（每日）+ 10（早修）+ 12（午休）
= 44 個，平均**每位師傅每週約 2 件任務**；有升旗的那天再多 19 個。

**排序權重**：每個維度（黑板／早修／升旗／午休／公差）各自排序，比較順序為
`該維度累計次數 → 總負擔 → 週別輪轉平手序 → staff_id`。

公平性只統計師傅，因為只有師傅會被排班；徒弟的五個計數恆為 0。
五個維度各自獨立排序、在統計頁各佔一欄：黑板、早修、升旗、午休、公差。

兩個關鍵設計：

1. **即時累加**：本次生成中每指派一次就立刻加回計數，避免整輪工作全塞給同一位歷史次數最低的人。
2. **週別輪轉平手序**：同分時的順序會依週起始日整體位移，避免低 `staff_id` 長期佔便宜；同時保持決定性。

人力不足時保留空名額（`staff_id = NULL`）並回報 `UNDERSTAFFED`，不會為了填滿而違反硬性限制。

## 換人與補位

點任一名牌開啟換人面板，**只列出師傅**，依 `該時段歷史次數 → 本週已排次數` 由輕到重排序。
空缺名額也可以從「公差」分頁的待補清單直接補。

衝突僅**提示**不阻擋（規格 §1 主管 100% 覆寫權）。偵測項目：人員停用、對方是徒弟、
本週該時段已有點位、本週已站過同一點位、當日已有黑板任務、已擔任全週職務。

## 公平性結算（規格 §4.5）

以**主管最終發布**的班表為準。發布時：

1. 沖銷本班表既有的 `fairness_ledger` 帳本列；
2. 依當前明細重新計算增量，寫入帳本並累加至 `fairness_stats`。

因此**重複發布不會重複累加**，撤回發布會完整沖銷；已發布班表的任何名額異動也會即時重新結算。
公差是隊裡的特殊任務，**計入統計**，在統計頁自成一欄。

## 手機介面配置

規格 §5 的頂部列在手機上重新配置為三層：

| 規格 §5 元素 | 手機位置 |
|---|---|
| 週次切換 | 頂部列箭頭；點中央日期回到本週 |
| 發布班表 | 頂部列右側；已發布時切換為「撤回」 |
| 一鍵自動排班 | 底部導覽中央凸起主按鈕 |
| 黑板區 | 「黑板」分頁，整週表格（任務 × 週一～週五） |
| 白板區 | 「白板」分頁 + 早修／升旗／午休分段控制；點位｜人員｜點位｜人員四欄表格 |
| 升旗日設定 | 「白板」→「升旗」分段，週一～週五切換鈕 |
| 公差指派 | 「公差」分頁，任務｜人員｜時間表格 + 待補名額 |
| 人力供需與升級徒弟 | 「統計」分頁 |
| 新增／刪除點位與成員 | 頂部列齒輪 → 「設定」面板 |

版面照實體班表做成表格：黑板是「任務 × 週一～週五」的整週表；白板是
「點位｜人員｜點位｜人員」的四欄表——左半欄放前半段點位、右半欄接著放後半段，
跟實體白板的兩欄寫法一致。早修與午休整週一張表，升旗則是每個升旗日各一組，
底下再分定點與巡查。

**換人操作**兩種都支援：
* 點一下名牌 → 開啟 Plan X 補位面板（主要方式，觸控最可靠）；
* 按住拖曳到另一個名牌 → 互換兩人（8px 位移門檻，避免誤觸）。

設計基準：米白底 `#FBFBFC`、Noto Sans TC 內文、Space Mono 數字（等寬對齊）、
寶石色編碼（翡翠＝早修、黃玉＝升旗、紫水晶＝午休、藍寶石＝黑板、紅寶石＝缺額）。所有觸控目標 ≥44×44px，文字對比皆達 WCAG AA，支援 `prefers-reduced-motion` 與深色模式。

## 設定後台

頂部列的齒輪打開「設定」面板，兩個分頁：

* **點位**：依時段分組（白板早修／升旗／午休、黑板全週／每日、公差任務）。
  每列可就地改名、用加減鈕調人數、刪除。上方表單新增點位——
  升旗會多出「定點／巡查」分區選擇；公差任務是手動指派的，不需要設人數。
* **成員**：依身分分組（師傅／徒弟）。每列可改名、升降身分、刪除。
* **備份**：匯出成一個 JSON 檔，或從備份還原。還原是整份取代，不做合併——
  合併規則沒有正確答案，覆蓋才可預期。兩種跑法的備份檔格式相同，可互相搬移。

單頁版的資料存在瀏覽器裡，清掉瀏覽器資料或換手機就會消失，**每次發布班表後匯出一份**。

改完關掉面板，按底部中央的閃電鈕重新排班即可。刪除採就地確認，
不另開對話框——巢狀 bottom sheet 在手機上容易誤觸。

刪除的連帶影響會直接寫在提示裡：刪點位會說移除了幾個班表名額，
刪成員會說有幾個名額變成空缺。

## API

| Method | 路徑 | 說明 |
|---|---|---|
| GET | `/api/week?week=YYYY-MM-DD` | 該週完整檢視（自動收斂到週一） |
| GET | `/api/week/navigate?week=&delta=` | 前後切換週次 |
| POST | `/api/week/generate` | 一鍵自動排班（覆蓋該週所有名額） |
| POST | `/api/schedules/:id/publish` | 發布並結算公平性 |
| POST | `/api/schedules/:id/unpublish` | 撤回並沖銷結算 |
| PATCH | `/api/assignments/:detailId` | 換人／清空名額，回傳衝突提示 |
| POST | `/api/assignments/swap` | 互換兩個名額 |
| GET | `/api/assignments/:detailId/plan-x` | Plan X 補位推薦名單 |
| POST | `/api/week/flag-days` | 設定本週的升旗日（`days: [1..5]`） |
| POST | `/api/specials` | 指派公差（任務、人員、可選日期與備註） |
| DELETE | `/api/specials/:detailId` | 移除公差指派 |
| GET | `/api/items` | 點位與任務清單 |
| POST | `/api/items` | 新增點位 |
| PATCH | `/api/items/:id` | 改名、調人數、改分區、調順序 |
| DELETE | `/api/items/:id` | 刪除點位（連帶移除班表上的名額） |
| GET/POST | `/api/staff` | 人員清單／新增 |
| PATCH | `/api/staff/:id` | 改名、升級／降級（`role`）、啟用／停用（`is_active`） |
| DELETE | `/api/staff/:id` | 刪除人員（班表名額變成空缺） |
| GET | `/api/backup` | 匯出整份資料 |
| POST | `/api/backup` | 從備份還原（整份取代） |
