# 雙板動態排班系統 Dual-Board Scheduling System

數位化實體「黑板（週矩陣）」與「白板（區域矩陣）」，提供排班主管一鍵極速排班、完全覆寫權與自動公平輪替。

* **使用者**：排班主管單一角色，單向由上而下發布。
* **編制**：師傅 22 位（高二組）進入排班池；徒弟 47 位（高一組）不排班、不計入點位人數，
  由主管手動升級為師傅後才會被排到班。
* **介面**：100% 手機優先的單頁看板（375px 起跳，支援深色模式與列印）。
* **系統邊界**：僅處理計畫班表，不涉及打卡、薪資與勞基法限制。主管具 100% 強制覆寫權。
* **技術**：Node.js 22 + 內建 `node:sqlite` + 原生前端，**零 npm 相依套件**。

---

## 兩種跑法

**伺服器版**（本機或內網，資料存在 SQLite）：見下方快速開始。

**單頁版**（`docs/index.html`，可直接放上靜態主機）：

```bash
node scripts/build-web.mjs   # 產生 docs/index.html
```

`docs/` 是 GitHub Pages 的標準來源目錄。在 repo 的
Settings → Pages 選 **Deploy from a branch → 分支 → /docs** 就會有公開網址，
不用登入、不用伺服器。

建置會把 `src/db/seed.sql` 的名冊與點位**內嵌進頁面**，第一次打開就有
69 人、42 個點位可用，不必手動建。之後所有異動都存在瀏覽器本機，
**務必用設定裡的匯出備份**——清掉瀏覽器資料或換手機就會消失。

建置產出兩份，內容相同只差外框：

| 檔案 | 給誰 | 差別 |
|---|---|---|
| `docs/index.html` | 靜態主機 | 完整 HTML 文件，含 viewport meta |
| `web/artifact.html` | Claude Artifact | 只有內容，平台發布時自己補外框 |

這件事不能混：靜態主機不會補 viewport meta，少了它手機會用 980px
桌面寬度渲染再縮小，整個介面變成一團小字。

領域邏輯（`src/domain`：排班引擎、公平性、Plan X）本來就是純函式、不碰資料庫，
兩種跑法共用同一份。只有資料層不同：

| | 伺服器版 | 單頁版 |
|---|---|---|
| 儲存 | SQLite（`src/db`） | 瀏覽器本機；放在 Artifact 上時改用雲端儲存 |
| 資料存取 | `src/services/repository.js` | `web/store.js` |
| 服務層 | `src/services/scheduleService.js` | `web/services.js` |
| API | `src/server`（REST） | `web/dispatch.js`（同樣的路徑與回傳格式） |
| 看板 | `public/app.js` | 同一份，建置時做 5 處修補 |

建置腳本的修補如果對不上 `public/app.js` 會直接失敗，不會默默產出壞掉的頁面。

## 排班演算法（規格 §4）

引擎是**純函式**：輸入人員、點位字典、公平性統計、公差事件與週起始日，輸出整週指派。相同輸入必得相同班表。

**排班池只有師傅**。徒弟不排班、不計入點位人數，也不會出現在班表上。

白板分**三個時段**：早修 → 升旗 → 午休。
升旗底下再分「定點」與「巡查」兩種任務，兩者屬同一時段、共用名額上限——
一個人在升旗時段只會站一個位置。

執行順序：

| 步驟 | 內容 | 硬性限制 | 軟性限制（可放寬） |
|---|---|---|---|
| A | Plan Y 預備隊 | 本週非整週缺席、不超過人力餘裕 | — |
| B | 黑板全週職務（交接、值日生） | 非預備隊、不重複擔任其他全週職務 | 整週皆可出勤 |
| C | 黑板每日職務（餐車、早修升旗、午休回來） | 非預備隊、當日可出勤、當日無其他黑板任務 | 非全週職務持有者 |
| D | 白板早修 → 升旗 → 午休 | 非預備隊、當日可出勤、**該時段僅站一個點位**、**當日不重複站同一點位** | — |

預備隊在最前面選，因為他們整週完全不排班——包含黑板任務。若放在最後選，
被選中的人往往已經背了任務，就不是真的待命。

### 人力上限（會直接限制點位設定）

每人每個時段只能站一個點位，因此：

```
單一時段的名額總數  ≤  可排班的師傅數
留作預備隊的人數    ≤  師傅數 − 尖峰時段名額數
```

系統在「統計」頁把這三個數字直接列出來，超過上限時回報 `CAPACITY_EXCEEDED`。
預備隊人數會自動讓位給實際名額——班表填不滿比沒有預備隊嚴重。

**目前配置**（點位取自實體白板照片）：早修 6 點 18 名額、升旗 19 點 19 名額、
午休 12 點 19 名額。22 位師傅扣掉 3 位預備隊剩 19 位，尖峰（升旗）剛好填滿。

每點人數由師傅人數反推：可排班人力平均攤到各點位，單點上限 3 人。
板面原本的人數（升旗 34、午休 28）遠超過 22 位師傅，無法照搬。
上工的 19 位師傅每人每週約 15 班（三個時段 × 五天幾乎全滿）。

**排序權重**：每個維度（黑板／早修／升旗／午休）各自排序，比較順序為
`該維度累計次數 → 總負擔 → 週別輪轉平手序 → staff_id`。

公平性只統計師傅，因為只有師傅會被排班；徒弟的四個計數恆為 0。
四個維度各自獨立排序：黑板、早修、升旗、午休。

兩個關鍵設計：

1. **即時累加**：本次生成中每指派一次就立刻加回計數，避免整輪工作全塞給同一位歷史次數最低的人。
2. **週別輪轉平手序**：同分時的順序會依週起始日整體位移，避免低 `staff_id` 長期佔便宜；同時保持決定性。

人力不足時保留空名額（`staff_id = NULL`）並回報 `UNDERSTAFFED`，不會為了填滿而違反硬性限制。

## Plan B 雙層備援

* **Plan Y（靜態）**：從師傅中挑 2~3 人，**整週完全不排班**，真正待命。
  挑選依據是 `standby_count`（擔任預備隊的次數）由少到多，平手時讓累計工作量最重的人休息。
  人力餘裕不足時會自動減少人數，甚至為 0，並回報 `STANDBY_SHORT`。

  用「本週負擔最輕」當標準會出問題：被選中的人本週歸零、下週依然最輕，
  預備隊會永遠卡在同一批人身上。獨立的待命次數才會輪替。

* **Plan X（動態）**：點任一名牌開啟補位面板。排序為
  `無衝突者優先 → Plan Y 預備隊優先 → 該時段歷史次數少者 → 本週已排次數少者`。
  **只列出師傅**，徒弟直接不進候選名單。

衝突僅**提示**不阻擋（規格 §1 主管 100% 覆寫權）。偵測項目：人員停用、當日公差、
當日同時段已有點位、早修午休點位重複、當日已有黑板任務、已擔任全週職務、對方是徒弟。

## 公平性結算（規格 §4.5）

以**主管最終發布**的班表為準。發布時：

1. 沖銷本班表既有的 `fairness_ledger` 帳本列；
2. 依當前明細重新計算增量，寫入帳本並累加至 `fairness_stats`。

因此**重複發布不會重複累加**，撤回發布會完整沖銷；已發布班表的任何名額異動也會即時重新結算。
公差事件不計入統計（規格 §2.2）；預備隊計入 `standby_count`，不計入工作量。

統計頁的均衡度會把待命週折算回來：每待命一週，補上該維度的每人每週平均值。
否則預備隊的 0 次會被誤判成「被排得太少」。環下顯示的仍是實際次數，不做修飾。

## 手機介面配置

規格 §5 的頂部列在手機上重新配置為三層：

| 規格 §5 元素 | 手機位置 |
|---|---|
| 週次切換 | 頂部列箭頭；點中央日期回到本週 |
| 發布班表 | 頂部列右側；已發布時切換為「撤回」 |
| 一鍵自動排班 | 底部導覽中央凸起主按鈕 |
| 已知公差登錄 | 「備援」分頁內 |
| 黑板區 | 「黑板」分頁 + 星期條 |
| 白板區 | 「白板」分頁 + 早修／升旗／午休分段控制 + 星期條；升旗再依定點／巡查分組 |
| Plan B 預備隊 | 「備援」分頁頂部卡片 |
| 人力供需與升級徒弟 | 「統計」分頁 |
| 新增／刪除點位與成員 | 頂部列齒輪 → 「設定」面板 |

白板矩陣在手機上不做表格：以**星期條選日 → 分段控制選時段 → 點位逐列**呈現，
一次只看一個時段的一天。點位用列不用卡——升旗有 19 個點位，攤成 19 張卡要滑很久，
而實體白板本來就是一行一個點位。

**換人操作**兩種都支援：
* 點一下名牌 → 開啟 Plan X 補位面板（主要方式，觸控最可靠）；
* 按住拖曳到另一個名牌 → 互換兩人（8px 位移門檻，避免誤觸）。

設計基準：米白底 `#FBFBFC`、Noto Sans TC 內文、Space Mono 數字（等寬對齊）、
寶石色編碼（翡翠＝早修、黃玉＝升旗、紫水晶＝午休、藍寶石＝黑板、紅寶石＝缺額、石墨＝預備隊）。所有觸控目標 ≥44×44px，文字對比皆達 WCAG AA，支援 `prefers-reduced-motion` 與深色模式。

## 設定後台

頂部列的齒輪打開「設定」面板，兩個分頁：

* **點位**：依時段分組（白板早修／升旗／午休、黑板全週／每日）。
  每列可就地改名、用加減鈕調人數、刪除。上方表單新增點位——
  升旗會多出「定點／巡查」分區選擇。
* **成員**：依身分分組（師傅／徒弟）。每列可改名、升降身分、刪除。
* **備份**：匯出成一個 JSON 檔，或從備份還原。還原是整份取代，不做合併——
  合併規則沒有正確答案，覆蓋才可預期。兩種跑法的備份檔格式相同，可互相搬移。

單頁版的資料存在瀏覽器裡，清掉瀏覽器資料或換手機就會消失，**每次發布班表後匯出一份**。

改完關掉面板，按底部中央的閃電鈕重新排班即可。刪除採就地確認，
不另開對話框——巢狀 bottom sheet 在手機上容易誤觸。

刪除的連帶影響會直接寫在提示裡：刪點位會說移除了幾個班表名額，
刪成員會說有幾個名額變成空缺。

## API

| Method | 路徑 | 說明 |
|---|---|---|
| GET | `/api/week?week=YYYY-MM-DD` | 該週完整檢視（自動收斂到週一） |

| PATCH | `/api/assignments/:detailId` | 換人／清空名額，回傳衝突提示 |
| POST | `/api/assignments/swap` | 互換兩個名額 |
| GET | `/api/assignments/:detailId/plan-x` | Plan X 補位推薦名單 |

| DELETE | `/api/absences/:id?week=` | 刪除公差紀錄 |
| GET | `/api/items` | 點位與任務清單 |
| POST | `/api/items` | 新增點位 |
| PATCH | `/api/items/:id` | 改名、調人數、改分區、調順序 |
