# 雙板動態排班系統 Dual-Board Scheduling System

數位化實體「黑板（週矩陣）」與「白板（區域矩陣）」，提供排班主管一鍵極速排班、完全覆寫權與自動公平輪替。

* **使用者**：排班主管單一角色，單向由上而下發布。
* **介面**：100% 手機優先的單頁看板（375px 起跳，支援深色模式與列印）。
* **系統邊界**：僅處理計畫班表，不涉及打卡、薪資與勞基法限制。主管具 100% 強制覆寫權。
* **技術**：Node.js 22 + 內建 `node:sqlite` + 原生前端，**零 npm 相依套件**。

---

## 快速開始

```bash
npm run reset    # 建立資料庫並灌入種子資料（36 位人員、25 個點位／任務）
npm start        # http://localhost:3000
npm test         # 51 個測試
```

環境變數：`PORT`（預設 3000）、`HOST`（預設 0.0.0.0）、`DB_PATH`（預設 `data/scheduling.db`）。

## 排班演算法（規格 §4）

引擎是**純函式**：輸入人員、點位字典、公平性統計、公差事件與週起始日，輸出整週指派。相同輸入必得相同班表。

執行順序：

| 步驟 | 內容 | 硬性限制 | 軟性限制（可放寬） |
|---|---|---|---|
| A | 黑板全週職務（交接、值日生） | 不重複擔任其他全週職務 | 整週皆可出勤 |
| B | 黑板每日職務（餐車、早修升旗、午休回來） | 當日可出勤、當日無其他黑板任務 | 非全週職務持有者 |
| C | 白板早修矩陣 | 當日可出勤、當日僅站一個早修點位 | — |
| D | 白板午休矩陣 | 同上，且**當日午休點位 ≠ 當日早修點位** | — |
| E | Plan Y 預備隊 | 本週非整週缺席 | — |

**排序權重**：每個維度（黑板／早修／午休）各自排序，比較順序為
`該維度累計次數 → 總負擔 → 週別輪轉平手序 → staff_id`。

兩個關鍵設計：

1. **即時累加**：本次生成中每指派一次就立刻加回計數，避免整輪工作全塞給同一位歷史次數最低的人。
2. **週別輪轉平手序**：同分時的順序會依週起始日整體位移，避免低 `staff_id` 長期佔便宜；同時保持決定性。

人力不足時保留空名額（`staff_id = NULL`）並回報 `UNDERSTAFFED`，不會為了填滿而違反硬性限制。

## Plan B 雙層備援

* **Plan Y（靜態）**：生成班表時挑出本週被指派次數最少、歷史總負擔最輕的 2~3 人，列於「備援」頁。
* **Plan X（動態）**：點任一名牌開啟補位面板。排序為
  `無衝突者優先 → Plan Y 預備隊優先 → 該時段歷史次數少者 → 本週已排次數少者`。

衝突僅**提示**不阻擋（規格 §1 主管 100% 覆寫權）。偵測項目：人員停用、當日公差、當日同時段已有點位、早修午休點位重複、當日已有黑板任務、已擔任全週職務。

## 公平性結算（規格 §4.5）

以**主管最終發布**的班表為準。發布時：

1. 沖銷本班表既有的 `fairness_ledger` 帳本列；
2. 依當前明細重新計算增量，寫入帳本並累加至 `fairness_stats`。

因此**重複發布不會重複累加**，撤回發布會完整沖銷；已發布班表的任何名額異動也會即時重新結算。公差事件不計入統計（規格 §2.2）。

## 手機介面配置

規格 §5 的頂部列在手機上重新配置為三層：

| 規格 §5 元素 | 手機位置 |
|---|---|
| 週次切換 | 頂部列箭頭；點中央日期回到本週 |
| 發布班表 | 頂部列右側；已發布時切換為「撤回」 |
| 一鍵自動排班 | 底部導覽中央凸起主按鈕 |
| 已知公差登錄 | 「備援」分頁內 |
| 黑板區 | 「黑板」分頁 + 星期條 |
| 白板區 | 「白板」分頁 + 早修／午休分段控制 + 星期條 |
| Plan B 預備隊 | 「備援」分頁頂部卡片 |

白板 10+ 點位 × 5 天的矩陣在手機上不做表格：以**星期條選日 → 分段控制選時段 → 點位卡直列**呈現，一次只看一個時段的一天。

**換人操作**兩種都支援：
* 點一下名牌 → 開啟 Plan X 補位面板（主要方式，觸控最可靠）；
* 按住拖曳到另一個名牌 → 互換兩人（8px 位移門檻，避免誤觸）。

設計基準：米白底 `#FBFBFC`、Noto Sans TC 內文、Space Mono 數字（等寬對齊）、寶石色編碼（翡翠＝早修、紫水晶＝午休、藍寶石＝黑板、黃玉＝備援、紅寶石＝缺額）。所有觸控目標 ≥44×44px，文字對比皆達 WCAG AA，支援 `prefers-reduced-motion` 與深色模式。

## API

| Method | 路徑 | 說明 |
|---|---|---|
| GET | `/api/week?week=YYYY-MM-DD` | 該週完整檢視（自動收斂到週一） |
| GET | `/api/week/navigate?week=&delta=` | 前後切換週次 |
| POST | `/api/week/generate` | 一鍵自動排班（覆蓋該週所有名額） |
| POST | `/api/schedules/:id/publish` | 發布並結算公平性 |
| POST | `/api/schedules/:id/unpublish` | 撤回並沖銷結算 |
| PATCH | `/api/assignments/:detailId` | 換人／清空名額，回傳衝突提示 |
| POST | `/api/assignments/swap` | 互換兩個名額 |
| GET | `/api/assignments/:detailId/plan-x` | Plan X 補位推薦名單 |
| GET/POST | `/api/absences` | 查詢／登錄公差 |
| DELETE | `/api/absences/:id?week=` | 刪除公差紀錄 |
| GET/POST | `/api/staff` | 人員清單／新增 |
| PATCH | `/api/staff/:id` | 啟用／停用人員 |
